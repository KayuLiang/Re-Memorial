# 背包 UI：功能范围与界面层级

日期：2026-09-22  
阶段：主界面与图片检视已接入 Ren'Py；实际消耗效果、关联状态与特殊确认仍待内容规则。见 `docs/handoffs/2026-09-22-inventory-renpy.md`。

## 1. 目标与范围

背包负责浏览当前持有的物品、查看图片与简介、理解效果，以及直接使用药物和食物。它不是未获得物品图鉴，也不承接病例、成长或任务管理。

本稿把上一轮推荐的首版功能列入计划，并加入“获得来源”和“关联状态跳转”。其他头脑风暴内容保留为后续候选，不默认全部实现。

优先原则：一个信息点，在同一可见界面中只有一个表达位置。不能通过换标题、换说法、换成图标，再重复一遍相同含义。

## 2. 功能分类

| 类别 | 首版计划 | 边界 |
| --- | --- | --- |
| 查找 | 分类、同类堆叠、数量、新物品标记、滚动浏览 | 不加入搜索、手动排序或拖拽整理 |
| 认识 | 图片、名称、简介、效果、已知获得来源 | 不编造缺失文案、规则、图片或来源 |
| 操作 | 单次食用、单次服用、使用条件检查、结果反馈 | 不批量使用；不能使用的物品没有虚假的可用按钮 |
| 检视 | 物品图片放大、缩放与平移、还原 | 不生成原素材不存在的背面、内部或三维模型 |
| 解释 | 从效果中的已知状态跳转到病例解释 | 复用已有状态档案，不在背包复制另一套百科 |
| 连续性 | 返回保留分类、滚动位置、选中物品；背包与药盒共用库存和使用规则 | 药盒的完整页面另行设计 |

## 3. 界面层级

```text
游戏常驻入口
└─ 背包主界面
   ├─ 分类导航                 同一界面的筛选，不是子页面
   ├─ 物品陈列                 同一界面的选择区
   ├─ 选中物品详情             同一界面的详情区
   │  ├─ 图片 → 图片检视       二级视图
   │  ├─ 状态名 → 病例解释     跳转既有界面，可返回背包
   │  └─ 食用／服用 → 结算     原位反馈，不打开结果页
   └─ 特殊消耗确认             仅有明确不可逆后果时出现
```

不会为分类、物品详情、使用成功分别增加独立页面。各层同一时间只有当前层响应输入。

## 4. 背包主界面

### 4.1 页面任务

回答三个问题：我有什么、选中物品有什么用、现在能做什么。

沿用已讨论的功能分区：左侧分类、中间物品陈列、右侧详情。本稿只规定信息归属，不固定最终像素、纹样和配色。

### 4.2 全局区与分类

- 页面标题仅“背包”一次，退出使用统一的粗十字。
- 分类：全部、药物、食物、重要物品。
- 分类自身的选中态表示当前范围，陈列区不再添加同义标题。
- 有其他已定义类别时再扩展分类，不为尚不存在的武器、材料等预留入口。
- 不显示库存总件数、类别计数、容量、重量等额外统计。
- 首次进入选择当前分类中的第一件物品；返回本次浏览时恢复原位置。空分类没有选中物品。
- 切换分类后显示该分类的首件物品；不沿用上个分类的不相关详情。

### 4.3 物品陈列区

每个格子只承担定位和选择，显示：

1. 物品缩略图。
2. 持有数量，固定在同一角落；只有一件时可省略“1”。
3. 尚未查看时的一处新物品标记。
4. 选中／键盘焦点的视觉反馈。

不显示名称、简介、效果、分类标签或第二组数量。名称集中到右侧详情；键盘焦点或点击选择即更新详情，不靠悬浮气泡再显示一份名称。

只有定义与使用效果相同、允许堆叠的物品才合并；有不同剧情身份或效果的物品不能只因名称相同而合并。

物品顺序保持稳定，新获得物品不让正在浏览的格子跳动。超出显示区域才出现滚动控件，不堆叠多组分页导航。

新标记在物品被实际选中、详情呈现后清除；仅经过鼠标悬浮不清除。一次获得多件同类物品不产生多枚标记。

无障碍名称可以包含物品名和数量供朗读使用，不另渲染成重复视觉文字。

### 4.4 详情区

按阅读顺序排列：

| 顺序 | 内容 | 功能与显示规则 |
| --- | --- | --- |
| 1 | 名称 | 全界面唯一的选中物品名称，不另加“物品详情”标题 |
| 2 | 完整图片 | 保持原图比例，不裁掉物品主体；可进入检视 |
| 3 | 简介 | 说明物品身份、外观或背景，不复述数值效果 |
| 4 | 效果 | 按实际规则显示使用或携带带来的变化 |
| 5 | 获得来源 | 只显示已知来源一句，不展开获取历史列表 |
| 6 | 操作区 | 一个主操作及其必要的不可用原因或结果反馈 |

缩略图用于在陈列中辨认位置，详情大图用于观察物品，两者尺度和职责不同；不再添加第三张装饰性同图。

效果的组织方式：

- 有主动消耗效果时标为“服用后”或“食用后”；有被动效果时标为“携带时”。两者不能混写。
- 数值变化、持续时间、代价或副作用只写在效果区，不另做一排复述同样信息的标签。
- 使用条件只在操作区表达；若当前不满足，用具体原因代替泛化的“无法使用”。
- 涉及已知状态时，状态名称本身可点击。只保留本物品施加该状态的强度、时间等必要信息，完整状态释义交给病例。
- 无效果的纪念物不硬塞“效果：无”；缺少设计数据也不能伪装成“无效果”。开发稿应明确标注效果待定义。
- 无来源记录则不显示来源区，不编造时间、人物或地点。
- 名称、简介、效果分别承担不同信息；简介不得写完效果之后再在效果区重复。

同类物品来自多个来源时，只在确有数据的前提下列出不重复的来源名；不新增按每一件追踪来源的系统。

### 4.5 操作与使用结果

- 点击格子只选中，不直接消耗物品。再次点击同一格子也不会使用。
- 药物主按钮为“服用”，食物为“食用”。一次操作消耗一件，具体消耗量以已确认规则为准；非一件消耗必须事先明确说明。
- 没有主动行为的物品不显示假“使用”按钮；未来已有明确功能的物品可用“阅读”等具体动词，不在本版自行创造行为。
- 使用前读取当时的库存与条件；不可用时不扣数量、不应用效果，并在操作区说明原因。
- 成功后，数量仅在陈列格子更新；操作区短暂显示本次实际产生的变化，不再次播报剩余数量或照抄完整物品效果。
- 反馈必须基于实际结算，不能把说明中的预期效果直接当作已发生结果。
- 同一笔使用尚未处理完时不接受重复激活；完成后仍允许玩家再次主动使用。
- 连续使用不改变分类和滚动位置，不跳回列表顶部。
- 最后一件用完后，当前格子与详情暂留为“已用尽”的浏览状态，数量位置统一显示该状态，操作按钮禁用；切换选择或离开后移除。该临时状态不构成已获得图鉴。
- 普通单次使用不弹确认窗。只有规则明确标记的重要不可逆消耗，才使用第 7 节的确认层。

## 5. 图片检视视图

任务：看清物品美术，不承担库存管理或使用操作。

- 从详情图片进入，主内容替换为大图；背包原来的格子和详情不在下层继续清晰展示。
- 显示物品名称一次、大图、必要的缩放／还原控制，以及一个返回入口。
- 不显示简介、效果、库存数量、获得来源或使用按钮。
- 滚轮缩放、拖动平移；提供可聚焦的等价控制，不强迫玩家只能使用鼠标手势。
- 小图不强行放大为虚假的高清细节。无可用素材时显示明确占位，不开放无意义的放大操作。
- 返回恢复原分类、滚动位置和选中物品；Esc 返回上层，不直接退出整个背包。
- 不加入翻面、三维旋转或包装阅读；它们需要对应素材和内容，属后续候选。

## 6. 关联状态解释

任务：理解物品效果里的状态名。

- 点击效果中的可跳转状态名，进入病例已有的状态解释，定位到对应条目。
- 跳转期间不叠加显示背包详情，也不新建“背包状态百科”。
- 保持病例原有的解锁与信息隐藏规则，不因跳转泄露未解锁效果。
- 未知或不可解释的状态不伪装成可点击链接。
- 本次从背包进入时提供明确的返回背包路径，返回恢复原选中项。
- 只查看解释，不改变拥有状态、状态持续时间或背包库存。

## 7. 特殊消耗确认层

这是条件性界面，不是每次使用的必经步骤。

- 仅用于设定已经明确的重要不可逆消耗，不由界面自行判断某件物品“贵重”。
- 只说明即将失去什么、不可逆后果，以及“取消／确认”两个操作。
- 名称在确认文本中出现一次，不叠加“确认使用某物品”的同义标题。
- 不重抄物品简介与整套效果；下层详情遮蔽且不可交互，避免同屏重复与误操作。
- Esc 或取消不产生任何效果；确认后回到主界面原位反馈。

## 8. 信息唯一归属表

| 信息 | 主界面唯一显示位置 | 明确禁止的重复 |
| --- | --- | --- |
| 所属功能 | 全局“背包”标题 | “我的背包”“背包物品”“库存”再次命名同一页 |
| 当前筛选范围 | 分类导航的选中态 | “全部物品”“当前分类：药物”等第二标题 |
| 选中物品名 | 详情区标题 | 格子名称、图片内标题、悬浮标签重复同名 |
| 持有数量 | 对应格子的数量位置 | 详情“拥有”、按钮剩余量、成功提示再报数量 |
| 新获得／未查看 | 对应格子的新标记 | 分类红点、详情“新物品”文字重复提示 |
| 简介 | 详情简介段落 | 图片说明、底栏滚动文字再次复述 |
| 本物品的效果 | 详情效果区 | 简介、标签、按钮旁同时重复效果 |
| 获得来源 | 详情来源行 | 简介中已说清的同一来源再重复；遇此情况整合为一处 |
| 不可用原因 | 操作区 | 灰按钮说明、悬浮提示、底部通知三处重复 |
| 本次实际变化 | 操作区临时反馈 | 同时弹通知、结果窗、屏幕底部重复播报 |
| 状态完整释义 | 跳转后的病例解释 | 在背包旁边再展开第二份同义百科 |

图片检视、确认层或病例解释进入后，原主界面相同信息应被替换或遮蔽；不能用“这是另一个面板”规避同一可见画面内的去重要求。

既有美术若自带可读名称或说明，应在排版时计入信息去重，而不是再机械覆盖一份文字。不能为去重擅改正式美术；冲突应在设计稿阶段提出。

## 9. 空态与异常

- 背包为空：陈列区一处“暂无物品”，详情区不再重复空提示。
- 分类为空：陈列区一处简短空态，清除上次详情；不伪造格子或物品。
- 图片缺失：用明确的“图片待补”占位，简介、真实效果仍可查看；不随意找替代物品图。
- 数据未登记：不静默吞掉已持有物品。开发阶段明确显示资料待补并阻止未定义操作。
- 效果尚未实现：明确区分“待实装”和“当前条件不允许”，不使用虚假的成功反馈。
- 长名称、长简介、较多效果：为详情内容提供滚动，主操作保持可达；不靠无限缩小字体塞下。

## 10. 与药盒的职责边界

- 背包可以查看并使用药物，不要求绕道药盒。
- 两个入口面对同一份库存、数量、使用条件和效果结算；一个入口使用后，另一个必须立即反映变化。
- 不在背包再加整套治疗、症状或服药管理面板；药盒是否承接这些内容，留到药盒需求阶段确认。
- “药盒”作为剧情获得的容器，与实际可服用药物不是同一概念。现有占位数据需在实际药物定义明确后衔接，不能把容器直接当药吃。

## 11. 首版内容准备与后续候选

### 实现前需补齐的内容

- 物品的稳定标识、分类、名称、简介、图片关联，以及是否可以堆叠。
- 具体药物／食物的使用条件、消耗与真实效果；相关数值、副作用不由 UI 设计编造。
- 获得来源仅引用现有剧情或记录，未记录的不强补。
- 修正已查明的项目登记问题：“奇怪的项链”与“项链”名称不一致，“帕尔的巧克力”未列入物品表；正式名称与食用效果仍需依据设定。
- 现有“使用”只显示占位文本，首版不能把这个按钮换皮后当作功能完成。

### 不列入首版

- 收藏／置顶、搜索、手动排序。
- 物品背面、信件阅读、剧情推进后的简介变化。
- 容量、负重、拖拽拼格子、装备槽。
- 丢弃、出售、分解、合成、批量服药。
- 未获得物品图鉴、获取历史流水、物品交易价格。

后续功能有真实内容支撑并单独确认后再增加，不预先放空按钮。

## 12. 设计与实现时的核对清单

- [ ] 同屏没有语义相同的重复标题、名称、数量、效果或反馈。
- [ ] 主界面可以完成找物品、看效果、单次使用，无不必要的来回跳转。
- [ ] 主动与被动效果区分清楚；没有效果、未知效果、尚未实现三者不混淆。
- [ ] 所有已持有物品可见，缺图与未登记条目不会被静默丢弃。
- [ ] 图片不拉伸、不截断主体；名称和较长内容不溢出。
- [ ] 格子、主操作、图片检视与状态链接支持可见键盘焦点。
- [ ] 返回逐层进行，保留分类、滚动和选中项。
- [ ] 使用结果来自真实结算，成功才更新库存，失败不消耗。
- [ ] 背包和药盒的库存、使用限制、效果一致。
- [ ] 空态、用尽、缺图、禁用与长文本都有明确呈现。
