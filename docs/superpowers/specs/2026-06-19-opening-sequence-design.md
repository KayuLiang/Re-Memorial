# Re: Memorial 完整开场与医疗系统设计

日期：2026-06-19

## 1. 目标与范围

本次实现替换游戏开始后的现有简短医疗确认段，完整实现《开头脚本》Scene 00–14，并在结束后接回当前 `script.rpy` 中“听北地的牧民说……”开始的神山回忆。

实现范围包括：

- 两页免责声明；
- `TAP TO START` 开始提示；
- 水滴与涟漪演出；
- 呼唤与两段急救记忆；
- 医疗系统载入与资料写入；
- 术前须知与可滚动知情同意书；
- 个人信息核对与正式属性分配；
- 长按签名、核验通过、断电与倒计时；
- 可复用的 CRT 三档效果；
- 后续玩法可直接使用的属性变量与接口位置。

倒计时只显示黑底白字 `3`、`2`、`1`。本次不制作倒计时 CG，也不制作最后的碎片 CG 闪回。

## 2. 已确认的视觉方向

整体为 lofi 仿 Win7 医疗系统界面，结合千禧年系统美学、梦核式失去上下文的熟悉感与电子示波器元素。

视觉基准：

- 桌面与环境使用低饱和莫兰迪医疗绿；
- 主窗口采用四边同色、同宽的经典 Win7 蓝色边框；
- 窗口内部保持清晰、扁平和可读，不使用写实径向渐变；
- 标题栏、窗口控制键、菜单栏和任务栏使用 Win7 Aero Basic 风格；
- 主体之外的桌面、任务栏和背景档案窗口整体压暗；
- 病历文书使用偏灰米色旧纸效果、宋体式正文与黑色遮挡条；
- 示波器使用低亮度、低饱和磷光绿；
- 像素粗糙感只表现为硬边、1px 明暗阶梯和克制的噪点，不降低正文清晰度；
- 窗口内容必须严格裁切在四边框内。

确认色彩基准：

- 医疗绿背景：`#6F8078`
- Win7 蓝框：`#5B8DB8`
- 旧纸病历：`#E7E4D9`
- 低亮磷光：`#A8C7AA`

实际 Ren’Py 实现可为层级对比做小幅明度调整，但不得改变低饱和、扁平、蓝框绿底的整体方向。

## 4. Scene 00–14 流程

### Scene 00：免责声明第一页

- 纯黑背景；
- 白色居中文字；
- 显示文档中的第一段免责声明；
- 停留 3 秒后自动进入 Scene 01；
- 不接受跳过该等待的点击操作。

### Scene 01：免责声明第二页

- 纯黑背景；
- 白色居中文字；
- 显示闪烁与光敏风险提示；
- “是”进入 Scene 02；
- “否”调用 `MainMenu(confirm=False)` 返回主菜单；
- 此处不叠加 CRT，优先保证可读性。

### Scene 02：开始提示

- 黑色背景；
- 像素感文字 `TAP TO START` 循环闪烁；
- 接受鼠标点击、空格、回车等常用继续输入；
- 输入后进入 Scene 03。

### Scene 03：水滴

- 黑色背景；
- 第一滴水由玩家输入触发下落；
- 落点产生圆形涟漪；
- 后两滴自动依次落下，音量略低；
- 涟漪扩散并淡出后进入 Scene 04；
- 优先使用 Ren’Py ATL 与简单图形素材实现。

### Scene 04：呼唤

- 黑屏；
- 居中显示“弗洛，弗洛——”；
- 预留远处模糊人声与轻混响音效接口；
- 短暂停顿后进入 Scene 05。

### Scene 05：系统初次载入

- 屏幕闪烁一次；
- 显示确认视觉稿中的 Win7 医疗系统桌面；
- 中央窗口显示灰色循环加载动画；
- 启用 CRT `subtle`；
- 显示主角台词“我听到有人在叫我的名字。”；
- 台词结束后进入 Scene 06。

### Scene 06：急救片段一

- 保留医疗系统画面；
- 覆盖 50% 透明黑色遮罩；
- 使用楷体或项目内可用的替代字体；
- 三句文字逐句向下累积，不清除上一句；
- 分别预留脚步、重物落地和急救现场喊话音效；
- 遮罩淡出后回到系统画面。

### Scene 07：系统介入

- 中央加载动画继续；
- 切换 CRT `interference`；
- 播放短促电流音效接口；
- 依次显示“精神卫生系统已介入。”“载入中。”；
- 进入 Scene 08。

### Scene 08：资料载入

- 背景快速层叠病历、访谈、诊断等窗口；
- 文件内容快速写入、滚动与覆盖；
- 前景显示绿色进度条；
- 加载提示在文档提供的候选文本之间变化；
- 预留键盘输入、翻页与低频电子噪音接口；
- 进度接近完成时短暂闪烁；
- 进入 Scene 09。

### Scene 09：急救片段二

- 保留当前系统画面并覆盖 50% 黑色遮罩；
- 四句楷体文字逐句向下累积；
- 预留风声、担架轮、金属摩擦、交接喊话和隔离门音效；
- 门关闭后短暂静默；
- 遮罩淡出，返回系统画面。

### Scene 10：术前须知

- 继续使用 Win7 医疗系统；
- CRT 回落为 `subtle`，提示前短暂增强；
- 弹出系统提示框；
- 显示“您好，这里是市立精神卫生中心服务系统，请仔细阅读术前须知。”；
- 进入 Scene 11。

### Scene 11：知情同意书

- 使用《系统背景界面》中的完整文书结构；
- 页面外观接近真实医院文件；
- 医疗关键内容与病历信息按文档使用黑色方框遮挡；
- 文书置于可滚动 viewport；
- 鼠标滚轮和滚动条拖动均可操作；
- 到达底部前“下一页”不可用；
- 到达底部后按钮变为可用；
- 主角与系统依次提示滚动和下一页操作；
- 点击下一页进入 Scene 12。

滚动到底的判定应基于 viewport 的实际滚动位置，而不是固定计时或任意点击。

### Scene 12：个人信息与属性分配

显示：

- 姓名：弗洛；
- 日期：空白方框或遮挡状态；
- CON、STR、DEX、INT、POW；
- 剩余可分配点数；
- 长按确认按钮。

姓名和日期按脚本要求分别插入短暂黑屏：

- 姓名黑屏显示“弗洛”；
- 日期黑屏显示白色空白方框；
- 然后返回资料页。

属性规则：

- `CON = 3`，固定且不可调整；
- `STR = 1`；
- `DEX = 1`；
- `INT = 1`；
- `POW = 1`；
- 额外可分配 17 点；
- 可调整属性最低 1；
- 每项最高 20；
- 剩余点数必须为 0 才能签名。

属性调整即时写入正式游戏变量。加减按钮在达到边界时禁用。

系统显示文档中的说明：

“关于你在这场手术中物质的使用，一经确认无法更改，请保证你充分利用它们的价值。”

长按签名规则：

- 按住确认按钮累计 1.5 秒；
- 松开过早立即将进度清零；
- 属性未分完时无法开始累计；
- 成功后锁定本次确认，避免重复触发；
- 进入 Scene 13。

### Scene 13：核验通过

- 状态灯与进度快速跳动；
- 依次显示“核验通过。”“医疗单元已就位。”“意识将在 3 秒内重启。”；
- 切换 CRT `shutdown`；
- 强闪、短暂横向错位或撕裂后断电黑屏；
- 进入 Scene 14。

### Scene 14：倒计时重启

- 纯黑背景；
- 居中显示白色大号数字；
- 依次显示 `3`、`2`、`1`；
- 不闪现 CG；
- 数字之间可保留轻微噪点或短促电流脉冲；
- 最后彻底黑屏并静默 2–3 秒；
- 关闭 CRT；
- 跳转至现有神山回忆。

## 5. 属性数据与预留接口

正式默认值：

```renpy
default stat_con = 3
default stat_str = 1
default stat_dex = 1
default stat_int = 1
default stat_pow = 1
```

分配规则常量：

- 可分配池：17；
- 最低值：1；
- 最高值：20；
- CON 不参与分配。

预留接口职责：

- `opening_stat_points_remaining()`：返回剩余点数；
- `opening_can_adjust_stat(stat_name, delta)`：检查增减是否合法；
- `opening_adjust_stat(stat_name, delta)`：执行一次合法调整；
- `opening_stats_complete()`：检查是否恰好分配完 17 点；
- `get_base_stat(stat_name)`：读取基础属性；
- `get_effective_stat(stat_name)`：后续接入 Mood、状态和临时修正；
- `get_attribute_dice(stat_name)`：后续建立属性骰组；
- `perform_attribute_check(...)`：后续建立统一检定入口。

接口命名在实施时可按 Ren’Py 现有风格微调，但职责必须保持分离。`get_attribute_dice()` 在公式建立前返回空元组；`perform_attribute_check()` 检测到空骰组时返回包含 `available=False`、属性名和原因的字典，不消耗精力、不投骰，也不虚构规则。

## 6. CRT 效果设计

复用现有资源：

- `crt_scanlines.png`
- `crt_noise_01.png`
- `crt_noise_02.png`
- `crt_noise_03.png`
- 扫描线滚动 ATL；
- 三帧噪点循环；
- 白色闪烁 ATL。

### `subtle`

用途：正常医疗系统页面。

- 极淡扫描线；
- 低强度噪点；
- 稀疏、弱闪烁；
- 不影响病历正文阅读。

### `interference`

用途：系统介入、资料载入和记忆切片返回。

- 中等扫描线和噪点；
- 更频繁短闪；
- 短促横向位移或局部错行；
- 与电流音效同步；
- 持续时间受剧情控制，不长期遮挡交互。

### `shutdown`

用途：Scene 13 断电。

- 瞬时强闪；
- 较强横向错位或撕裂；
- 噪点迅速增强后消失；
- 直接切黑；
- 不能在切黑后留下持续白层。

CRT screen 继续保持非 modal。免责声明不使用 CRT。需要交互的文书页面只能使用 `subtle`。

如果项目中没有正式音效：

- 每个音效使用稳定的目标路径；
- 播放前通过 `renpy.loadable()` 检查文件，缺失时静默继续并保持演出时序；
- 后续替换正式文件时不需要重写剧情流程。

- 涟漪；
- 低强度纸张或像素纹理；

## 8. 错误处理与交互约束

- 免责声明“否”必须可靠返回主菜单；
- 属性不能低于 1 或高于 20；
- CON 不可调整；
- 不能分配超过 17 点；
- 未分完点数不能签名；
- 提前松开长按必须清零；
- 长按成功只能返回一次；
- 知情同意书未到底不能进入下一页；
- CRT 不得阻塞鼠标和键盘操作；
- 所有临时 screen 必须在场景结束时关闭；
- 开场结束后不得遗留任务栏、CRT、遮罩或系统窗口；
- 从开场中途读档时，screen 默认值必须能恢复到一致状态。
